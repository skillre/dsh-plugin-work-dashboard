# 导出 POC 收集表单（v3）

生成一个**自包含 HTML** 文件：组员双击就能填，无需服务器、无需联网、无需 GitHub 账号。

## 怎么生成

用随本 skill 发布的脚本，不要去找外部脚本（旧版的 `~/dsh-test/poc_form.py` 是 v1 生成器，
产出的 YAML 台账已经读不了）：

```sh
# 补全模式：给已有项目补字段 / 追加一条进展
node <skill-dir>/scripts/export-form.mjs \
  --mode fill \
  --poc ~/.dsh/cache/work-dashboard/repo/projects/POC-006.yaml \
  --out /tmp/表单-POC-006.html

# 批量：多个项目打包成一个表单
node <skill-dir>/scripts/export-form.mjs \
  --mode fill \
  --poc "~/.dsh/cache/work-dashboard/repo/projects/*.yaml" \
  --out /tmp/表单-批量.html

# 新建模式：从零建一个新项目
node <skill-dir>/scripts/export-form.mjs --mode new --out /tmp/表单-新建.html
```

`<skill-dir>` 就是本 skill 所在目录（`skills/poc-export/`），模型可通过
`resourceBase` 解析相对路径。脚本只读 YAML、只写 HTML，不改台账。

## 表单填什么

按 v3 分组，和台账结构一致：

| 区块 | 字段 |
|---|---|
| 身份 | 项目名称、体系、主业公司、部门、金额（万元）、项目类型、阶段、状态、负责人、销售、客户技术责任人、业务决策人 |
| G0 | 客户为什么测、我们为什么测、决策链、测后客户决策、竞争对手 |
| 计划（G1/G2） | 客户痛点、期望认可、成功指标（2–3）、验证场景（3–5）、我方赢点、风险（≤3）、G1 结论、G2 Ready |
| 进展（核心） | 日期、类型、目标、范围、实际、完成度、证据（标题+链接+类型）、客户同步对象/反馈/认可、G3-1、G3-2、下一步（目标/负责人/截止） |
| 结论 | 目标达成、客户认可、我方证据、剩余风险、证明了什么、客户认可了什么、下一步业务动作、Next Milestone（含负责人/截止/状态）、总体结论 |

**进展是追加的，不是覆盖的。** 组员填的是一条新进展，提交时追加到 `progress[]` 末尾，
不改历史条目——这是 v3 的核心约束。

## 表单内置功能

| 功能 | 说明 |
|---|---|
| 自动保存 | 停止输入 2 秒后自动存 localStorage；另可随时点【保存】 |
| 草稿恢复 | 重新打开自动恢复上次未提交内容 |
| 清空草稿 | 顶部按钮 |
| 实时缺口提示 | 顶部显示当前填了多少、还缺哪几项必填 |
| 预览 JSON | 底部按钮，看将交回的结构 |
| 提交并生成文件 | 下载 `poc-changes-<日期>.json` |

存储键由**项目编号**派生（不是时间戳），所以同一个项目的表单重新生成后仍能找到旧草稿。

## 交给组员时要说清

1. **怎么打开**：双击 HTML，用浏览器打开
2. **填哪些**：灰色区域是台账已有信息，只填需要补充的部分
3. **不用怕丢**：自动保存，关掉再打开还在
4. **填完怎么给你**：点【提交并生成文件】，把下载的 `.json` 用飞书发回
5. **填不全没关系**：留空的会被标出来，提交时统一校验

## 注意

- 生成的文件只在本地（`/tmp` 或指定位置），**不会自动发给任何人**；需要你自己发给组员。
- 组员交回的是 `.json`（不是 `.yaml`）。刻意的：JSON 更严格，不容易被手改坏，
  而且提交前要经过校验。
- 不要用旧版 `poc_form.py`：它产出 v1 字段，台账读不了。
