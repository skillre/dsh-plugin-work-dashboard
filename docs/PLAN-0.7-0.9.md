> 本文件是 P0–P3 优化的落地计划，不是设计愿景。每条都写清了**改哪个文件、验收什么、为什么不先做别的**。
> 目标来自一次对真实台账（`skillre/workbranch` @ `7b81b63`，30 个项目）的实测：progress 0 条、plan 全空、
> outcome 全空、四维覆盖 0/30。插件最精细的四块（进展流、四维、时间线、风险看板）在真实数据上**全是空态**。

## 2. P0（0.7.0）

### P0-3 阻障口径统一（先做，因为 P0-1/P0-2 都要读它）

**问题**：待处理栏只覆盖 12 条缺口规则。真实数据里"4 个项目没填金额""1 个项目没有
`stage_since`""30 个项目没有进展记录"这些阻障在栏外。

**做法**：Host 新增聚合 `BlockerBoard`，把四类阻障合成一个带来源标签的列表：

1. `gap` —— 12 条缺口规则（已有 `scanGaps`）
2. `stalled` —— 阶段停滞（复用 R12 的判定，但不重复计数）
3. `missing-amount` —— `amount_wan` 为 0
4. `no-progress` —— 没有任何 progress 记录
5. `no-stage-since` —— 没有 `stage_since`，因此无法判断停滞

**为什么合并**：这五类在用户眼里是同一个问题——"哪里卡住了"。分开放在三个地方，
用户要自己拼。合并后一个列表能排序、能计数、能下钻。

**文件**：`src/blockers.ts`（新）、`src/types.ts`、`src/transport.ts`、`src/index.ts`、
`src/client/shell.tsx`、`src/client/overview.tsx`、`src/client/text.ts`

**验收**：
- 真实台账上，阻障总数 = 缺口数 + 金额缺失 + 无进展 + 无 stage_since（去重后不重复计数）
- 每个阻障带来源标签，可按来源筛选
- 空态文案说清"没有阻障"而不是"没有数据"

### P0-1 阶段感知详情页

**问题**：详情页是 `ProgressStream → DimensionGrid → Gate0Meter → PlanPanels → OutcomePanel`
写死的五段。G0 阶段的项目打开后，看到的是三个空区块，而"我还差哪几项才能进 G1"要自己拼。

**做法**：按 `summary.stage` 决定骨架顺序与显隐：

| 阶段 | 骨架 |
|---|---|
| **G0** | G0 工作台（五必填逐项 + 决策链 + 评审状态）→ 为什么测（why_customer / why_us）→ 进展流（可空） |
| **G1** | 计划面板（痛点 / 指标 / 场景 / 优势）→ G1 结论 → 进展流 |
| **G2** | G2 前置条件 → 进展流 → 计划 |
| **G3** | 进展流 → 证据链 → 客户认可 → 四维 |
| **G4** | 四维 → 结论 → Next Milestone → 进展流 |
| `closed` | 结论 → 四维 → 进展流（归档视图） |
| 未知 | 保持现有全量顺序 |

**关键约束**：不是隐藏区块，是**排序 + 收起到折叠区**。任何字段都不能因为阶段而不可达——
否则用户没法核对上一阶段的记录。

**文件**：`src/client/detail.tsx`、`src/client/css/detail.ts`、`src/client/text.ts`、`tests/view.spec.tsx`

**验收**：G0 项目首屏出现"G0 工作台"且不出现空的进展流；G4 项目首屏出现四维；
所有阶段都能展开看到全部五个区块。

### P0-2 空态改工作清单

**问题**：30 个项目同时空，页面重复 30 次"还没有进展记录"，信息量为零。

**做法**：`dtProgressEmpty*` 这类空态从"描述性空"改成"可执行清单"：
- G0 空态 → 列出还缺哪几个必填字段 + 一句"填完导出表单给组员"
- 无进展 → 列出"这个项目还没有第一条进展记录" + 指向导出表单位置

**文件**：`src/client/detail.tsx`、`src/client/overview.tsx`、`src/client/text.ts`

**验收**：空态区块包含具体字段名（不是泛泛的"暂无数据"）；测试断言字段名出现在空态里。

## 3. P1（0.8.0）

### P1-1 KPI 顶条

`总数 / 进行中 / 各阶段数 / 预算合计 / 阻障数`，点击任一项等价于应用对应筛选。
数据来自已有的 `snapshot.stats`（**注意：这块现在算了但从没渲染，P3 一并处理**）。

### P1-2 预算面板

总额拆分（已评审通过 / 待评审 / 未填）、按体系分布、集中度、未填金额警示。
现在这是三张图偶然拼出来的，改成一块有明确口径的面板。

### P1-3 阶段内完成度

六根柱在 30:0:0:0:0:0 的数据下没有信息量。改为双层：外层是漏斗位置，内层是当前 Gate
的完成度（G0 = 五必填 x/5）。

### P1-4 详情基本信息补全

- 客户名：`org.system / org.company`（Host 已下发，Client 从未渲染）
- 客户人：`tech_owner`（客户技术责任人）+ `exec_sponsor`（业务决策人）
- 责任人：`owner`
- 预算：`amount_wan`
- 决策链：`gate0.decision_chain` 从 G0 计量条提出来，作为基本信息的一块
